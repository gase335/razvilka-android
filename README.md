# Развилка (Razvilka)

Портативный клиент протокола **csqtt** (многопоточный туннель через TURN-серверы звонков VK) для Windows 10/11 x64.
Форк FOCSQ: протокольное ядро `csqtt-core` (папка `backend/`) сохранено и используется без изменения протокола,
поверх него добавлены раздельное туннелирование, правила для приложений, работа нескольких конфигураций
одновременно и режим прокси-сервера.

## Быстрый старт

1. Распакуйте `razvilka-windows-x64.zip` в любую папку (рабочий стол, флешка — установка не нужна).
2. Запустите `razvilka.exe`. Программа всегда запускается с правами администратора (Windows покажет запрос UAC) —
   они нужны виртуальному адаптеру туннеля.
3. **Серверы → Вставить ссылки csqtt://** — вставьте ссылку на сервер (или «Добавить вручную»: адрес, порт, пароль).
4. **Серверы → Хеши звонков VK** — вставьте ссылки на звонки VK (или хеши). Вход в аккаунт VK не нужен и не поддерживается — только ручные хеши.
5. **Подключение** — два независимых переключателя: **Туннелирование** (трафик этого компьютера) и
   **Прокси-сервер** (SOCKS5/HTTP для браузера и устройств в сети). Можно включить один или оба сразу.

Туннель по умолчанию работает в режиме «Чёрный список» с пресетом «Россия напрямую» (зоны .ru .su .рф … и
российские IP по GeoIP). Прокси по умолчанию — «Всё через VPN»: сайты видят регион сервера.

## Состав папки

| Файл | Назначение |
|---|---|
| `razvilka.exe` | приложение (GUI, ядро сессий, прокси — всё в одном файле) |
| `wintun.dll` | драйвер виртуального адаптера Wintun 0.14.1 (WireGuard LLC), нужен туннелированию |
| `WebView2Loader.dll` | загрузчик Microsoft WebView2 — окно капчи VK (если ядро не решило её само) |
| `geoip.dat` | база «IP → страна» (DB-IP IP to Country Lite, CC BY 4.0) |
| `data\` | создаётся при запуске: `settings.json`, `logs\` |

Никаких Docker/WSL/виртуальных машин. Если папка программы недоступна для записи (например, `Program Files`), данные
пишутся в `%APPDATA%\Razvilka`. Драйвер Wintun Windows устанавливает автоматически при первом создании адаптера
(поэтому программа запускается с правами администратора); адаптер «Razvilka» удаляется при отключении.

## Возможности и как они устроены

### Туннелирование
Страница «Туннелирование», три режима:

* **Всё через VPN** — весь трафик компьютера, через выбранный сервер или через все (наименее загруженный);
* **Белый список** — через VPN идут только программы/домены/IP/страны из списка, у каждой записи свой сервер
  (конкретный или «все серверы»); остальное напрямую;
* **Чёрный список** — через VPN всё, кроме списка (он идёт напрямую).

Программы проверяются раньше доменов/IP/стран; внизу страницы — «Активные правила» в том порядке, в каком их
проверяет программа. Изменения применяются сразу, без переподключения.

Создаётся адаптер Wintun (`172.19.0.1/30`, DNS `172.19.0.2`), маршруты `0.0.0.0/1` и `128.0.0.0/1` (и `::/1`, `8000::/1`)
ведут в него. Для каждого нового соединения маршрутизатор определяет:

* **процесс-владелец** — по таблицам `GetExtendedTcpTable`/`GetExtendedUdpTable`;
* **домен** — по DNS: все DNS-запросы Windows направляются (NRPT + DNS адаптера) во встроенный DNS-перехватчик,
  который запоминает соответствие IP → домен;
* **страну** — по `geoip.dat`;

и применяет первое подходящее правило:

* **Через VPN** — сырой IP-пакет уходит в сессию ядра, адрес источника меняется на адрес в туннеле (NAT).
  TCP остаётся сквозным — работает системный стек Windows, без переупаковки;
* **Напрямую** — пакет принимает пользовательский TCP/IP-стек, который открывает настоящее соединение через
  физический адаптер (`IP_UNICAST_IF`): сайт видит реальный IP пользователя;
* **Блокировать** — TCP RST / ICMP «запрещено», для доменов — NXDOMAIN.

DNS-запрос идёт той же стороной, что и трафик домена: для доменов «напрямую» — DNS вашего провайдера,
для остальных — DNS сервера внутри туннеля (без утечек).

Типы записей: программа (имя .exe, полный путь, папка `D:\Games\*` — через «Обзор…» или из списка запущенных),
домен (`example.com` со всеми поддоменами, `full:`, `keyword:`, кириллические зоны), IP/подсеть (IPv4/IPv6 CIDR),
страна (ISO-код по `geoip.dat`).

### Несколько конфигураций одновременно
Каждая сессия — отдельный процесс ядра csqtt (`razvilka.exe --core`, ядро хранит состояние в глобальных
переменных, так конфигурации полностью независимы; упавшая сессия перезапускается сама).

* **Агрегация на уровне протокола (реальная).** Конфигурации одного сервера (адрес + порт + пароль) при
  включённом объединении становятся одной сессией: хеши VK объединяются (до 6), TURN-потоки суммируются
  (до 162). Протокол csqtt сам раскладывает каждое соединение по всем потокам, а сервер собирает поток
  обратно — растёт скорость даже одной загрузки. Это поддерживается сервером штатно.
* **Разные серверы — автоматически наименее загруженный.** Каждое новое соединение получает сервер с наименьшей
  нагрузкой (соединений на рабочий поток). Исключение — записи и режимы, где на страницах «Туннелирование» и
  «Прокси-сервер» выбран конкретный сервер. У серверов разные внешние IP, поэтому одно TCP-соединение целиком
  идёт через один сервер; суммируется скорость многих соединений. Склеить одно соединение между разными
  серверами невозможно без поддержки на сервере (MPTCP/bonding) — протокол csqtt этого не предоставляет.
* **Хеши звонков.** Один хеш VK достаётся только одной записи (до 27 потоков на хеш). Общие хеши раздаются
  записям по одному по кругу; если хешей меньше, чем записей, лишние записи не запускаются, а на странице
  «Серверы» видно, кому сколько досталось. Один хеш на нескольких подключениях VK наказывает «Flood control».
* **Автоперезапуск** (Настройки, включён по умолчанию): дважды в секунду каждый сервер проверяется DNS-запросом через
  туннель. Сервер перезапускается, если 1,5 с нет ответа (и не меньше 2 неудачных проверок подряд) или 10 с
  ждёт капчу. При этом:
  * если не отвечает и DNS роутера/провайдера напрямую — пропала сеть целиком, никого не перезапускаем, ждём сеть;
  * серверы перезапускаются по одному, не чаще раза в 20 с;
  * после ответа VK «Flood control» сервер 3 минуты не перезапускается — ядро повторяет запрос само;
  * не подключившийся сервер перезапускается, только если ядро 2 минуты не пишет в журнал (зависло).

  Кнопка «Перезапустить» у каждого сервера на странице «Подключение» — вручную.

### Прокси-сервер
Один порт, протокол определяется автоматически: SOCKS5 (CONNECT и UDP ASSOCIATE, логин/пароль по RFC 1929),
SOCKS4/4a, HTTP-прокси (обычные запросы и CONNECT, Basic-авторизация). Прокси слушает только на указанном
пользователем IP — по умолчанию подставляется адрес компьютера в локальной сети, поэтому прокси доступен и
этому компьютеру, и другим устройствам в сети. Работает одновременно с туннелем или отдельно, на тех же сессиях.

* Сервер для прокси — конкретный или все (наименее загруженный); на странице видно, какой сервер сейчас
  обслуживает соединения прокси.
* Правила прокси (Всё через VPN / Белый список / Чёрный список; домены, IP, страны) задаются в отдельном окне
  «Правила прокси-сервера» и не зависят от правил туннеля.
* Если клиент передаёт имя сайта («прокси DNS» в FoxyProxy, `socks5h`), имя резолвится DNS сервера внутри
  туннеля — сайт видит регион сервера. Если клиент передал только IP, а правила прокси не пустые, имя сайта
  берётся из TLS SNI / заголовка Host первого пакета.
* Прямые соединения прокси привязываются к физическому адаптеру, поэтому не попадают в туннель, даже когда он включён.
* Кнопка «Открыть порт в брандмауэре Windows» — для доступа с других устройств.

### Интерфейс
Подключение (два переключателя, скорость, серверы с кнопкой «Перезапустить»), Серверы (ссылки `csqtt://`,
общие хеши VK, распределение нагрузки), Туннелирование, Прокси-сервер, Статистика (последние соединения:
программа или клиент, сайт, маршрут, правило), Журнал, Настройки (автоперезапуск, DNS, IPv6, отпечаток TLS).
Пояснения спрятаны в значки «(?)». Цвета маршрутов: янтарный — через VPN, синий — напрямую.

В текстовых полях работают Ctrl+C / Ctrl+V / Ctrl+X / Ctrl+A (и в русской раскладке), а по правой кнопке — меню «Вырезать / Копировать / Вставить / Выделить всё / Очистить».

Запуск без окна: `razvilka.exe --headless [tunnel] [proxy]` — использует `data\settings.json`, Ctrl+C — остановка.

## Ограничения (честно)

* **IPv6 через туннель не передаётся** — сервер выдаёт только IPv4-адрес. IPv6-соединения с правилом «через VPN»
  отклоняются (приложения переходят на IPv4), AAAA-записи для таких доменов не отдаются; «напрямую» IPv6 работает.
* **Доменные правила опираются на DNS.** Если программа резолвит имена сама через DNS-over-HTTPS (например,
  «Безопасный DNS» в Chrome/Firefox), домен для её соединений неизвестен — сработают только правила IP/стран/приложений.
  Разные домены на одном IP (CDN) получают маршрут последнего запрошенного домена.
* **Правила приложений не влияют на DNS**: в Windows имена резолвит служба DNS-клиента, а не сама программа.
* Подсети VK (TURN и API ядра) всегда идут напрямую — так требует протокол (как и в FOCSQ).
* Отрисовка окна: DirectX 12/Vulkan (wgpu), при сбое программа сама перезапускается с OpenGL
  (принудительно — переменная окружения `RAZVILKA_RENDERER=glow`).
* Без WebView2 Runtime окно капчи не откроется; автоматическое решение капчи ядром работает и без него.
* Прокси: фрагментированные UDP-пакеты SOCKS5 (FRAG≠0) не поддерживаются (как и у большинства серверов).
* Flutter-интерфейс FOCSQ не используется: его нельзя собрать в этой среде, а лицензия FOCSQ запрещает
  переиспользование их дизайна, названия и логотипа в модификациях. Интерфейс написан заново (egui).

## Что проверено

* Юнит-тесты (21): разбор/NAT пакетов и контрольные суммы, DNS, правила (белый/чёрный список, приоритет программ,
  GeoIP RU, подсети), балансировка по нагрузке, план сессий/агрегация, ссылки `csqtt://`, сниффинг SNI/Host.
* Сквозные тесты (`client/tests/e2e.rs`) с имитатором ядра `--mock-core` (тот же протокол событий и UDP-пакетов,
  за ним — «интернет» на smoltcp): туннель — DNS через туннель и напрямую, NAT, балансировка, программа важнее
  IP-правила, путь «напрямую», UDP; одновременно с ним прокси на тех же сессиях; прокси отдельно — SOCKS5/HTTP,
  правила, определение сайта по Host; автоперезапуск «замолчавшего» сервера.
* GUI (Linux-сборка + имитатор): все страницы, окно правил прокси, смена режима и закрепление записи за
  сервером на лету — запросы через прокси сразу пошли через выбранный сервер.
* Windows-сборка запускалась под Wine: открытие окна, портативная папка `data\`.
* **Не проверено в этой среде:** реальный Windows с драйвером Wintun (туннель), реальные серверы csqtt и VK —
  к ним нет доступа. Код туннеля компилируется под Windows и использует те же механизмы, что и FOCSQ
  (Wintun, IP Helper API, NRPT), но первый запуск на реальной машине стоит провести с журналом перед глазами.

## Сборка из исходников

Требования: Rust 1.97+, для кросс-сборки из Linux — `mingw-w64` и исходники std (`rust-src`).

```bash
cd client
# Windows (нативно, MSVC или GNU):
cargo build --release --features webview
# Кросс-сборка из Linux:
RUSTC_BOOTSTRAP=1 cargo build --release --features webview \
  --target x86_64-pc-windows-gnu -Z build-std=std,panic_unwind
# Тесты (Linux/Windows):
cargo test --no-default-features --features mock -- --test-threads=1
```

`tools/build_geoip.py` пересобирает `geoip.dat` из свежих CSV DB-IP, `tools/make_icon.py` — иконку.

## Структура

```text
backend/        ядро csqtt-core (протокол, воркеры, TURN) — из FOCSQ; добавлены хук исключений и события LISTEN/EXCLUDE
client/src/
  engine/       сессии (дочерние ядра), маршрутизатор VPN, DNS/хаб, балансировщик, стек туннеля, прокси, VK API
  rules/        правила и GeoIP
  net/          разбор IP/TCP/UDP/ICMP/DNS, NAT
  sys/          Windows: Wintun, маршруты, NRPT, процессы, DPAPI
  gui/          интерфейс
  childhost.rs  режим `--core`
  webview.rs    окно капчи VK (WebView2)
dist-assets/    wintun.dll, geoip.dat
tools/          сборка geoip.dat и иконки
```
