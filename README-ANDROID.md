# Развилка для Android — порт

Порт десктопного клиента **Развилка** (csqtt/FOCSQ) на Android (телефоны и планшеты).
Движок, протокольное ядро и split-tunnel переиспользованы из вашего кода; добавлены
Android-слой поверх `VpnService`, JNI-мост и приложение.

---

## Что это и почему так устроено

Ваше ядро `backend/` (`csqtt-core`) **изначально было Android-библиотекой** (upstream
csqtt — Flutter+Rust приложение). Форк FOCSQ/Развилка добавил десктопный слой `client/`
(движок, правила, Windows-TUN, GUI на egui). Поэтому порт — это не переписывание, а
**возврат ядра на Android и перенос движка Развилки поверх `VpnService`**.

Ключевой факт: вся платформенная развязка в движке уже вынесена за трейты
`VpnNetwork` / `TunIo` и `cfg`-переключение `sys/windows.rs` ↔ `sys/other.rs`. Добавлен
третий путь — `sys/android.rs`.

### Архитектура на Android

```
  другие приложения                 ваше приложение (один процесс)
        │ IP-пакеты                  ┌─────────────────────────────────────┐
        ▼                            │  Rust (librazvilka_android.so)        │
  ┌───────────┐  fd   ┌─────────┐    │  ┌───────────┐   UDP 127.0.0.1  ┌────┴─────┐
  │ VpnService│──────▶│ sys/    │───▶│  │  движок    │◀───────────────▶│ csqtt-core│──▶ VK TURN
  │  (Kotlin) │ TUN   │ android │    │  │ router/    │    (loopback)   │ (in-proc) │   (в обход
  └───────────┘       │ (TunIo) │    │  │ rules/     │                 └───────────┘    туннеля)
        ▲             └─────────┘    │  │ geoip/     │                                     │
        │ addDisallowed              │  │ tstack/    │                                     │
        │ Application(self)          │  │ proxy      │                                     │
        └── трафик приложения мимо VPN └──┴───────────┘─────────────────────────────────────┘
```

* **TUN даёт `VpnService`**, а не ядро. Kotlin получает fd из `establish()` и отдаёт
  его в Rust (`nativeSetTunFd`). `sys/android.rs` оборачивает fd в `TunIo`
  (чтение/запись через `poll`+`eventfd`, чтобы `interrupt()` будил читателя).
* **Маршруты/адреса/DNS настраивает `VpnService.Builder`** (половинные маршруты
  `0.0.0.0/1 + 128.0.0.0/1`, адрес `172.19.0.1/30`, DNS `172.19.0.2` — как на десктопе).
  Netlink/root не нужны.
* **Обход туннеля для TURN/VK** достигается `addDisallowedApplication(собственный пакет)`:
  весь трафик приложения (сокеты ядра к TURN и «прямые» соединения движка) идёт мимо
  VPN автоматически. Per-socket `protect()` не требуется — поэтому в ядре не понадобился
  отдельный хук.
* **Ядро работает в этом же процессе** (на Android нельзя запустить APK как CLI-child),
  в tokio-задаче через `csqtt_core::run_client`. События/логи/исключения забираются
  через существующий `set_log_callback` (он уже отдаёт и `__CSQTT_EVENT__|…`, и
  `CAPTCHA_SOLVE|…`), управление — через `submit_control_line` / `submit_captcha_result`.
  Пакеты туннеля по-прежнему идут по UDP на `127.0.0.1` (loopback в том же процессе).

## Что работает

- ✅ Системный VPN через `VpnService` (телефон и планшет, без root).
- ✅ Протокол csqtt поверх TURN-звонков VK — ядро без изменений.
- ✅ Split-tunnel по **домену / IP / стране** (GeoIP), режимы «Всё через VPN /
  Чёрный список / Белый список», пресет «Россия напрямую».
- ✅ Автоперезапуск сессии, DNS-перехват, выбор отпечатка TLS, режимы капчи.
- ✅ Ссылки `csqtt://` (оба формата FOCSQ) разбираются в приложении.
- ✅ Капча в режиме `auto` решается самим ядром (без WebView).
- ✅ Живой журнал и статус в UI.

## Ограничения этого порта (осознанные)

- ⚠️ **Один сервер за раз.** Ядро хранит каналы управления/капчи/логов в глобальных
  переменных; на десктопе несколько сессий работают как отдельные процессы, а
  во встроенном режиме Android одновременно активна одна сессия. JNI-слой оставляет
  включённым только первый сервер. Мультисервер потребует вынести эти глобали ядра в
  инстанс (см. «Дальнейшие шаги»).
- ⚠️ **Правила «Программа» (per-app) не поддерживаются** — на Android нет
  `GetExtendedTcpTable`/`/proc/net` по чужим приложениям без root. Работают
  домен/IP/страна. (Альтернатива — `VpnService.addAllowedApplication` на весь туннель,
  задаётся при establish; не реализовано в UI.)
- ⚠️ **Прокси-сервер** в UI не выведен (в ядре поддержан; на телефоне применяется редко).
- ⚠️ **WebView-капча (`wv`)** — рабочий каркас; точное извлечение токена зависит от
  текущего потока VK, а исходный WebView-слой upstream в предоставленных исходниках
  отсутствовал. Основной путь — `auto` (решает ядро), он от WebView не зависит.

## Что проверено, а что нет

- ✅ **Переиспользуемый Rust** (ядро + движок + правила + geoip + user-space стек +
  прокси + `sys/other` + headless) собирается под `x86_64-unknown-linux-gnu` без ошибок.
- ✅ **Android-специфичный Rust** (`sys/android.rs`, встроенный запуск ядра в `session.rs`,
  JNI-мост) типопроверен на хосте через фичу-симулятор (Android использует обычные
  Linux-API: `eventfd`/`poll`/`dup`/tokio — отличается только `cfg`).
- ❌ **Кросс-компиляция под Android и сборка APK не выполнялись**: в среде разработки нет
  Android SDK/NDK, а `dl.google.com` недоступен. Финальная сборка — на вашей машине
  (ниже). Kotlin не компилировался — возможны мелкие правки, которые подсветит
  Android Studio.
- ❌ **На живой инфраструктуре VK/TURN не тестировалось** (нет устройства и хешей звонков).

## Сборка

### Требования
- **Android Studio** (Koala/Ladybug 2024+) или Android SDK CLI.
- **Android NDK** (напр. `27.1.12297006`) — SDK Manager → *NDK (Side by side)*.
  Версию пропишите в `android-app/app/build.gradle.kts` → `ndkVersion`.
- **Rust** с Android-таргетами:
  ```bash
  rustup target add aarch64-linux-android armv7-linux-androideabi \
                    x86_64-linux-android i686-linux-android
  ```
- JDK 17.

### Шаги
1. Откройте папку `android-app/` в Android Studio (он подхватит Gradle wrapper).
   Либо через CLI — сначала создайте wrapper: `cd android-app && gradle wrapper`.
2. Убедитесь, что Gradle видит NDK (`local.properties`: `sdk.dir=…`, либо
   `ANDROID_HOME`/`ANDROID_NDK_HOME`).
3. Сборка:
   ```bash
   cd android-app
   ./gradlew assembleRelease     # или assembleDebug
   ```
   Плагин `rust-android-gradle` сам кросс-компилирует `android-jni/` в
   `librazvilka_android.so` для всех ABI и кладёт их в APK.
4. APK: `android-app/app/build/outputs/apk/…`.

> Первая сборка Rust (`aws-lc-rs`, `rustls`, tokio…) под 4 ABI занимает время. Для
> быстрой проверки оставьте в `cargo { targets = … }` только `"arm64"` (реальные
> устройства) и/или `"x86_64"` (эмулятор).

### Структура
```
backend/        ← ваше ядро csqtt-core (БЕЗ изменений)
client/         ← движок Развилки + sys/android.rs + встроенный запуск ядра
android-jni/    ← НОВЫЙ cdylib: JNI-мост (librazvilka_android.so)
android-app/    ← НОВЫЙ проект Android Studio (Kotlin + VpnService + Compose UI)
```

Полный список правок в `client/` — в `CHANGES-ANDROID.md`.

## Как пользоваться (на устройстве)
1. Запустить приложение → вставить `csqtt://`-ссылку (или ввести адрес/порт/пароль).
2. Вставить хеши звонков VK.
3. Выбрать режим туннелирования (по умолчанию «Чёрный список» + пресет «Россия напрямую»).
4. «Подключить» → система один раз спросит разрешение VPN.
5. Статус и журнал — на главном экране.

## Дальнейшие шаги (если нужно развивать)
1. **Мультисервер:** вынести глобальные каналы ядра (`CONTROL_TX`, `ACTIVE_CAPTCHA`,
   `LOG_CALLBACK`, `EXCLUDE_HOOK`, `EVENTS_FORCED`) в передаваемый инстанс-хендл —
   тогда несколько сессий пойдут в одном процессе. Сейчас это единственное, что
   удерживает один сервер.
2. **Per-app split-tunnel:** через `VpnService.Builder.addAllowedApplication/
   addDisallowedApplication` (грубее десктопа — задаётся при establish, без горячей смены).
3. **WebView-капча:** свериться с реальным ответом VK и доработать извлечение токена
   в `CaptchaActivity` (сейчас — по параметрам `token/captcha_key/key`).
4. **DNS провайдера:** пробросить системные DNS из `ConnectivityManager` в
   `razvilka::sys::set_direct_dns` (сейчас для «прямых» доменов используются публичные
   резолверы 1.1.1.1 / 8.8.8.8).
5. **Прокси-сервер:** вывести в UI (ядро уже умеет).
